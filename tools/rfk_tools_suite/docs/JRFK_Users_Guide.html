01 System Architecture & Introduction to JRFK.exe

The JRFK 32-to-64-Bit Migration & Diagnostic Suite provides a bulletproof upgrade path for the RF-KIT RF2K-S and RF2K+ amateur radio power amplifiers. Over years of broadcast and contest operation, legacy 32-bit Raspberry Pi operating systems suffer from lack of upstream security patches, driver deprecation, and slow single-core telemetry polling. JRFK upgrades your amplifier to a high-performance, 64-bit Debian Trixie (aarch64) appliance while guaranteeing zero data loss and total preservation of all factory calibrations.

The Dual-Architecture Model: PC vs. Amplifier Separation

To avoid confusion, the JRFK ecosystem is split into two completely separate, decoupled components:

Component Hardware Host Port / Access Core Function & Scope
PC Migration Utility (JRFK.exe) Windows PC (Host) Port 8089 (Local) One-time offline SD card migration. Reads 32-bit GOLD SD, verifies safety signatures, wipes and partitions target MicroSD, writes the ~6.28 GB 64-bit OS image, stages factory calibrations, Wi-Fi credentials, and sets up turnkey firstboot. Has NO runtime web sub-pages.
Amplifier Appliance Suite Raspberry Pi (Inside Amp) Port 8088 (LAN) 24/7 operational station diagnostics. Natively hosts the Technical Blueprint web interface: Antenna Mapper, Health Monitor with 60°C emergency thermal trip, Remote Screen mirror, automated weekly backups, System Report, and Log Viewer.

03 Post-Migration Web Diagnostics Suite (Port 8088)

Once your amplifier is booted into 64-bit, navigate to http://<amplifier-ip>:8088/. The top navigation bar provides instant access to seven unified tools:

1. 🗺️ Antenna Mapper & Tuner Bode Plot (/antenna)

Directly reads your amplifier's config.json and renders your active relay state across the 4 coaxial antenna ports:

  • Active 4-Port Relay Matrix: Displays four physical port cards (ANT 1, ANT 2, ANT 3, ANT 4). The currently energized relay glows green with ● ACTIVE RELAY while the remaining three show STANDBY.
  • Dynamic Band Routing: As you switch bands (e.g. 160m → 20m → 6m) either on the transceiver, via CAT, or clicking the on-screen band ribbon, the antenna port cards instantly update to reflect your amplifier's actual relay matrix.
  • Bode Plot & Physical Values: Displays the ATU SWR matching curve across all segment boundaries (marked with |). Clicking any segment displays the physical Inductance in nanohenries ($L$ in nH / $\mu$H) and Capacitance in picofarads ($C$ in pF).

2. 📈 Health Monitor & 60°C Thermal Guard (/health)

Provides mission-critical telemetry monitoring designed to protect your LDMOS transistors under heavy contest duty cycles:

  • 5 Real-Time Telemetry Gauges: Heatsink Temperature (°C), Forward Output Power (W), Reflected Power & SWR, 53.5V DC Rail Voltage, and Drain Current (A).
  • 3 Real-Time Canvas Charts: Historical charts tracking PA temperature trends, RF envelope power, and DC rail stability under high-current load.
  • Multi-Tier Thermal Safety System:
    • Nominal (≤ 50°C): Normal operation. Front/rear fans engage automatically above 42°C.
    • Warning (> 50°C): High duty-cycle warning displayed on web banner.
    • Red Alert (> 55°C): Approaching safety ceiling; warning logged.
    • Emergency Thermal Trip (> 60°C): Automatic unkey protection! The suite triggers an emergency RPC command to force the amplifier into Standby, activates a 300-second live cooldown countdown modal overlay, and locks out re-enabling until the heatsink cools below 50.0°C.

3. 📺 Remote Screen Console (/screen)

Streams a crisp, real-time mirror of the physical 1024x600 amplifier screen directly into your browser:

  • Operates via the Raspberry Pi's secondary display pipeline as a virtual HDMI monitor.
  • Strictly READ-ONLY, preventing accidental touches or parameter changes.
  • Ideal for propping up an iPad, tablet, or smartphone beside your logging computer during a contest.

4. 💾 Disaster Recovery & SD Backup Manager (/backup)

Manages automated and on-demand cloning of your active production storage:

  • Secondary SD Architecture: A secondary 32GB MicroSD card is placed in a small USB 2.0 reader plugged into the Raspberry Pi rear USB port (labeled BACKUP-AUTO).
  • Weekly Automated Cron: Every Sunday at 04:00 GMT, the system generates a compressed binary raw disk image (dd | xz) saved to /home/pi/backups/.
  • On-Demand Backups: Click "⚡ Run Full SD Backup Now" anytime before performing firmware modifications or shack rewiring.

5. ⚙️ Automated RPi OS Autopatching (Sunday Cron)

Keeping an embedded Linux system secure and stable normally requires manual terminal access. JRFK automates this safely:

  • Immediately after the weekly raw image backup completes on Sunday morning, the cron executes sudo apt update && sudo apt upgrade -y.
  • Benefits: Keeps the 64-bit kernel, hardware drivers, OpenSSH, and security packages permanently updated without operator intervention.
  • Fail-Safe Protection: Because a complete compressed backup image was written minutes prior, you can instantly roll back if an upstream Debian package ever introduces an issue.

6. 📋 System Report (/report)

An exhaustive, publication-grade technical report covering all hardware and software subsystems:

  • Host Hardware: CPU clock rates, SoC silicon temperature, memory allocation, and undervoltage/throttling register flags.
  • Storage Health: Root filesystem usage, wear-leveling indicator (A2 high-endurance rating), and interface bus speed.
  • Network & CAT: IP address, MAC address, Wi-Fi RSSI signal quality, active CAT rig, and UDP port bindings.
  • Calibrations: Detector null voltage offsets (0.042V / 0.038V) and full 64-bit validation audit.

7. 📜 Log Viewer (/logs)

Centralized real-time access to four diagnostic log streams:

  • telemetry_rolling.log: 10MB rotating circular log tracking typ, min, and max values for temperature, power, voltage, and current.
  • rfk_backup.log: Audit log of weekly scheduled backups, compression times, image sizes, and apt package upgrades.
  • rfk_gui: Live stdout/stderr log from the RF-KIT touch UI, SimpleRPC serial packets, and CAN bus commands.
  • systemd journal: Kernel boot messages, USB serial device attachment (/dev/ttyUSB_RFK), and networking events.

FIRMWARE PREREQUISITE: Your RF-KIT amplifier must run firmware version v199, v200, or later prior to starting the migration. Internal controller parameter schemas were updated in v199 to support 64-bit SimpleRPC protocol parity.

05 The Golden Rule of Safety: Creating GOLD1 & GOLD2

Before writing a single byte of 64-bit software, you will clone your existing 32-bit working system into two physical Golden Masters directly on the Raspberry Pi using the desktop SD Card Copier tool (piclone):

  1. Boot the amplifier normally into your 32-bit system. Plug a blank 32GB MicroSD card into a USB reader connected to the Raspberry Pi.
  2. Open the Raspberry Pi desktop menu → Accessories → SD Card Copier.
  3. Select Copy From Device: Internal SD Card (/dev/mmcblk0).
  4. Select Copy To Device: USB Card Reader (/dev/sda).
  5. Click Start. Once complete, remove the card and label it GOLD1.
  6. Repeat this exact procedure with a second blank card and label it GOLD2.
ZERO RISK ACHIEVED: You now possess two independent, bootable, exact physical copies of your factory 32-bit system. Even in the worst-case scenario, re-inserting GOLD1 returns your amplifier to 100% factory operation in under 60 seconds.

06 Option 1: 64-Bit OS Migration with JRFK.exe

With GOLD1 created, you can now generate your production 64-bit SD card (PROD-64) using the Windows PC utility:

STEP 1 Launch JRFK.exe on Windows

Connect your USB MicroSD reader to your Windows PC with GOLD1 inserted. Launch JRFK.exe. Accept the Windows UAC Administrator prompt. The tool will automatically open your default browser to http://127.0.0.1:8089/.

STEP 2 Read-Only GOLD Asset Extraction

Click 1. Validate & Extract GOLD SD. JRFK reads the Linux ext4 rootfs in strict read-only mode, validating your callsign, Wi-Fi SSID, calibration files, and tuning tables. It computes SHA-256 signatures to confirm data integrity.

STEP 3 Swap to Target Blank SD Card

Eject GOLD1 and safely store it in your shack vault. Insert a fresh blank 32GB card (labeled PROD-64). Click Rescan Disks and select the target drive.

STEP 4 Write 64-Bit Image & Inject Factory Calibrations

Click 2. Provision SD (Migrate to 64-Bit). JRFK wipes the card, flashes the verified 64-bit Debian Trixie image (~6.28 GB), and injects all your preserved calibrations, Wi-Fi network credentials, headless SSH keys, and custom 1024x600 display modelines.

07 The 3-Boot Walkthrough: From Automation to Production

Insert the newly created PROD-64 card into your amplifier's Raspberry Pi and power on. The amplifier will perform an automated 3-boot initialization:

  • Boot 1 (Partition Expansion & Offline Debs): The system auto-expands the Linux rootfs to utilize the full 32GB card, unpacks the 15 offline Debian packages, installs Python 3.13 shims, and reboots automatically (~90 seconds).
  • Boot 2 (Hardware Link & Controller Handshake): The system tests the USB serial link to the Arduino / proprietary controller (/dev/ttyUSB_RFK). Once verified, it displays a green completion confirmation and reboots into production mode.
  • Boot 3 (Production Mode): Boots directly into the fullscreen 1024x600 RF-KIT touchscreen GUI. The Linux desktop is completely hidden. All RF-KIT meters, antenna ports, and menus are live.

08 Option 2: Virgin Fresh 64-Bit Setup (Without GOLD Card)

If your original 32-bit SD card was lost or corrupted, JRFK allows building a complete, clean 64-bit OS from scratch:

  1. Open JRFK.exe and navigate to Option 2: Fresh Setup.
  2. Enter your Callsign, Shack Wi-Fi SSID and Password, and select your transceiver CAT rig.
  3. Click Build Fresh 64-Bit SD. JRFK generates a turnkey 64-bit image populated with standard K7BIT cookbook tuning profiles ready for on-air alignment.

09 Emergency Disaster Recovery & Field Hot-Swap

If your primary production SD card ever experiences hardware degradation or read errors during a contest:

THE 3-MINUTE RECOVERY PROCEDURE:
  1. Switch AC mains power to OFF. Disconnect AC power cord. Wait 30 seconds for power supply capacitors to bleed down.
  2. Press and remove the degraded card from the internal Raspberry Pi slot.
  3. Insert your BACKUP-AUTO card (from the rear USB reader) or your pre-provisioned FIELD-64 card into the internal slot.
  4. Reconnect AC power and switch power to ON. The amplifier boots immediately into full operation with all calibrations intact.
